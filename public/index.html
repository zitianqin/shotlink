MCP · Vercel Blob

image-self-host-mcp

Upload a local image, get a public unguessable URL. Built to embed screenshots in GitHub PRs — no browser, nothing committed to the repo.

The endpoint

One authenticated route. It stores bytes in Vercel Blob and returns a public, CDN-served URL that GitHub renders inline (even on private repos).

POST /api/upload

Set up the MCP tool

The upload_image tool runs locally and talks to this endpoint. Wire it into Claude Code once:

  1. Clone & build the MCP server

    git clone https://github.com/zitianqin/image-self-host-mcp
cd image-self-host-mcp
npm install && npm run build

  2. Get your upload token

    This is the shared secret the endpoint checks. Whoever deployed the Vercel project set it as the UPLOAD_TOKEN env var — copy that same value.

    # if you deployed it, read or (re)generate:
vercel env pull            # pulls into .env.local
# or mint a fresh one:  openssl rand -hex 32  → vercel env add UPLOAD_TOKEN

  3. Register the server with Claude Code

    claude mcp add-json --scope user image-host '{
  "command": "node",
  "args": ["/ABS/PATH/image-self-host-mcp/dist/index.js"],
  "env": {
    "IMAGE_HOST_ENDPOINT": "https://image-self-host-mcp.vercel.app/api/upload",
    "IMAGE_HOST_TOKEN": "<your UPLOAD_TOKEN>"
  }
}'

  4. Use it

    In a new Claude Code session, call the tool (or just ask to add a screenshot to a PR):

    upload_image(path="/abs/path/shot.png")
# → https://<hash>.public.blob.vercel-storage.com/shot-<random>.png

gh pr edit 123 --body "![screenshot]($URL)"

Security

Capability URLs. Returned links are public but unguessable — the same model GitHub's own user-attachments uses. Anyone with a link can view the image; nobody can guess it. Fine for UI screenshots. If an image holds PII, treat the link as sensitive — an unguessable link is still exfiltratable if it leaks. Blobs live forever until deleted.
